Portfolio case study · Reconciler · property accounting close

Present Reconciler as a designed human-agent contract, not a screen tour

Most "AI product" portfolios show a chat box with a sparkle icon. You built something rarer: a supervised multi-agent pipeline where three agents do the work, a person approves at exactly the points that carry risk, and the person's decisions teach the system. The walkthrough should make that architecture visible. The screens are evidence, not the story.

Everything below is grounded in the actual build: the reducer, the seed, the design decisions log, the V2 workspace spec, and the running app.

01The positioning thesis

A senior hiring panel is not judging whether you can lay out a dashboard. They are judging whether you can decide what an agent should do alone, what it must show, where a human must decide, and how the human's decisions change the agent. Say that sentence early, then spend the rest of the walkthrough proving each clause.

The one-liner to open with

"Reconciler is a monthly bank-close product for property accountants. Three agents read statements and ledgers, match them, and post the result back to Yardi. My job was to design the contract between those agents and the controller who signs off: what runs unattended, what needs a signature, what the system has to prove, and how a reviewer's correction becomes a rule the agents follow next month."

Four clauses, four proofs

ClauseWhat it means in agentic designWhere Reconciler proves it
Autonomy boundaryWhich steps run without a person, and why those steps are safe to delegate.Intake and matching run unattended. Reconciliation runs the four accounts in parallel. Posting to Yardi never starts without a click.
LegibilityThe person can always answer "what is it doing, what did it do, why."Present-tense core, append-only activity log, per-record reason and evidence, agent timelines, confidence per match.
Approval gatesHuman decisions sit at the frontier of the work, on the irreversible actions."Start reconciliation", "Review N records", "Post to Yardi". The CTA lives where the work stopped.
Learning loopA correction is captured as durable guidance, and the system reports whether it ever fires.Reviewer notes, "Teach this rule", Knowledge base with scope and "applied N× this cycle", stale rules flagged at zero.

02Vocabulary you should own

Use these terms in the voiceover and the case study. Each card names the concept, defines it plainly, and points at the thing in your product that embodies it. Never use a term you cannot point at.

Agentic workflow vs. chatbot
A chatbot answers. An agentic workflow takes a goal, runs multi-step work with tools, and returns a result. The interface is about supervision, not conversation.
Yours: no chat surface at all. The user drops documents and reviews a verdict.
Orchestration and handoff
Splitting work into specialised agents that pass state to each other in a fixed order.
Yours: Intake → Reconciliation → Summary, each with its own role line, prompt, and timeline.
Human-in-the-loop (HITL)
A person is a required step in the pipeline, not an optional observer.
Yours: the "review" run state. Nothing posts until a person opens the records.
Approval gate
A deliberate stop before a consequential action. The action is offered where the work paused.
Yours: "Post to Yardi" in the review drawer header, only while run state is review.
Levels of autonomy
A ladder from "suggest" to "act and inform" to "act silently". Each step in a pipeline can sit at a different rung.
Yours: intake acts and informs, matching acts and routes low confidence to a person, posting waits for a signature.
Confidence and approval floor
The agent scores each decision; below a threshold it defers to a human instead of acting.
Yours: per-record confidence chips (19% to 52%) and the prompt rule "below the property's approval floor goes to a reviewer".
Calibrated trust
The user trusts the system exactly as much as it deserves: neither over-relying nor ignoring it.
Yours: "Settled on its own" is frozen from the agent's verdict and cannot improve when a human approves leftovers.
Observability
The system exposes its internal progress and history so a person can follow and audit it.
Yours: activity log, agent timelines, strand states, "Matching 4 accounts · 2 complete".
Explainability
Each decision comes with the reason and the evidence it rests on, in the user's language.
Yours: Reason + Evidence on every exception: "No matching ledger entry within ±3 days · Statement line 47".
Provenance
Where a fact or rule came from, and when.
Yours: rules carry capture date, the session they came from, and the record title that prompted them.
Append-only audit log
History is never rewritten. Later human edits do not alter what the agent originally reported.
Yours: activity entries keep their reconcile-time counts after a reviewer moves records.
Steerability and memory
How a person changes agent behaviour, and what the agent carries between runs.
Yours: Knowledge base rules in prose, scoped to portfolio or property, read before every run. No numeric settings anywhere.
Guardrails
Hard constraints the agent cannot cross regardless of its own judgement.
Yours: "Post only records a human has approved." "Never report a total you have not been given." "Never infer a date or an amount."
Tool use and side effects
An agent calling an external system. Writes are the dangerous class of call.
Yours: Yardi posting is the one write, and it gets the only hard gate, plus a hold rule for month-end.
Blast radius and reversibility
How much damage a wrong action can do, and whether it can be undone. Autonomy should shrink as blast radius grows.
Yours: record moves have Undo toasts; posting has no undo, so it has a gate.
Graceful failure
Failure is a designed state with a route back, not a blank screen.
Yours: "failed" run state with the system's note, "Rerun", and the distinction between an exception and an unclassified file.
Evaluation
Measuring whether the agent is right, not just whether it ran.
Yours: first-pass accuracy, success rate per agent, records per reviewer hour, six-cycle trend.
Cost per unit of work
Tokens are the bill. Cost only means something against output.
Yours: tokens split in / out / cached per agent, and "tokens per record" as the trend figure.
Progressive disclosure of agent work
Show the present at a glance; keep the full record one click away.
Yours: the core shows one agent; the log collapses to four rows; timelines expand on demand.
Honest state (no premature certainty)
Never display something the system has not learned yet.
Yours: "Identity is an output of intake, not an input." Rows appear only after a document is read and resolved.
Ironies of automation
The better automation gets, the less practice the human has for the cases it hands back. Reviewer skill must be protected.
Yours: reviewer hours down 57%, so exceptions carry full evidence for a person who now sees fewer of them.

The trust surface map, spelled out

One annotated composite. Number each callout and use the same numbers in the video.

  1. Header: standing facts only. "4 accounts · 8 documents · 204 records · 8 open". Never narrates.
  2. Core: present tense, one agent, animated field that never pauses. Draft is the exception: it is the dropzone.
  3. Activity log: past tense, append-only, deduped. Notes that changed an outcome appear as "Applied note · …" next to the work they changed.
  4. Agent timelines: what each of the three did, with the two unclassified files named.
  5. Summary band: Reconciled, Settled on its own, Need review, Net difference. Net difference can veto the others.
  6. Record row: confidence chip, reason, evidence lines, reviewer note, approve / flag with Undo.

  8. AI Performance: token split, success rate per agent, records per reviewer hour trend.

05Video walkthrough script

Target 7 to 8 minutes for the full cut and a 60-second cut for the portfolio hero and LinkedIn. Structure it by lifecycle, because the lifecycle is the argument. Each beat lists what is on screen and what you say. Speak in first person, past tense for decisions, present tense for what the product does.

Rule for the voiceover

Every beat must contain one decision and the reason for it. "Here is the dashboard" is a tour. "I moved the primary action to the header because the dashboard's only job is triage and the old 64px bar competed with the list it served" is a portfolio.

0:00
Cold open: the problem
Screen
Black. Then the Dashboard: "First-pass accuracy 90%", "5 of 12 posted to Yardi".
Say
"Every month a property accountant reconciles bank statements against the ledger for every property they manage. Four bank accounts, hundreds of lines, and a controller who has to sign the close. Reconciler puts three agents on that work. I designed the contract between those agents and the person who signs."
0:35
Thesis and architecture
Screen
Diagram A. Highlight the three agents, then the three gates, then the amber knowledge loop.
Say
"Three agents in sequence: Intake reads and normalises, Reconciliation matches and explains, Summary writes the close and posts. Four questions drove every screen: what runs alone, what must it show, where does a person decide, and how does that decision change next month's run. Autonomy is set per step. Matching runs unattended because its output is a proposal. Posting waits for a signature because it is an external write with no undo."
1:30
Draft: the honest empty state
Screen
Open a not-started property (1500 Park St). Workspace with the core alone. Drop eight files.
Say
"The session opens with one square and nothing else. No ghost rows, no checklist. That was a deliberate reversal. My first version pre-drew a row per bank with the logo and account number already on it, so the moment a file landed it looked identified. The system had not read anything yet. Identity is an output of intake, not an input, so now the canvas only shows what the agent actually knows: a filename and a size."
2:20
Intake: land, read, resolve, dock
Screen
Let the intake sequence play. Rows fly out. Strands draw. Hover a row to show hover isolation. Open the activity log: "Received 8 documents · Filenames only · nothing read yet."
Say
"Watch the order. A document lands anonymous, the core reads it, resolves the institution and whether it is a statement or a ledger, then it docks to its bank and side. The first file is a ledger whose statement has not arrived, so it waits. Filenames like document (4).pdf are on purpose: intake reads contents, it does not trust labels. The activity log underneath is append-only and in the past tense. The core is the present tense. One surface for each, never both."
3:15
Gate 1 and parallel matching
Screen
"8 documents paired across 4 accounts" with Start reconciliation in the core. Click. Four banks matching at different speeds.
Say
"The first gate. Reconciliation is 58% of the token bill, so the person confirms the input set before it runs. Then four accounts match in parallel. The first build ran them one at a time because the controller was sequential, and the canvas claimed three banks were idle while one worked. The UI was describing the code, not the work. They now finish at different moments, because a synchronised finish reads as fake."
4:00
Summary band: four numbers, one decision
Screen
Summary band. Point at each figure. Hover "Settled on its own".
Say
"The controller is deciding one thing: can I close this cycle. So the band shows four numbers and refuses everything else. Reconciled is the denominator. Settled on its own is the autonomy figure. Need review is the work owed. Net difference can veto the other three, because a reconciliation that does not tie is not finished. Settled on its own is frozen from the agent's verdict. If the reviewer approves all eight leftovers it still says 96%. It is a claim about the agent, and it must not flatter itself."
4:50
Gate 2: review with evidence
Screen
Review drawer. Exceptions filter. Expand "Stripe payout": Reason, Evidence, confidence 32%. Approve one. Show the Undo toast and the header count dropping from 8 to 7. Type a reviewer note.
Say
"Every exception carries the reason, the evidence lines, and the confidence the agent had. Right amount and wrong vendor is the failure this product exists to catch, so counterparty similarity is never enough on its own. Decisions live in the session state, not the drawer. A decision that evaporates when the panel closes is not a decision. Move a record and the header, the band, and the bank row all update, with Undo. The log keeps its original counts. History is not rewritten."
5:45
The learning loop
Screen
Knowledge tab: "Stripe payouts post 2 banking days after settlement · Reconciliation · Applied 6× this cycle". Then the "Not applied this cycle" rule. Cut to AI Performance › Knowledge base with portfolio and property scopes.
Say
"This is the only place a person changes how the agents behave. No sliders, no thresholds. Rules are written in the reconciler's own words, scoped to one property or the whole portfolio, and read before every run. Each rule reports how often it fired. A rule at zero has never matched, which means it is redundant or worded too narrowly, and someone should look at it. That is observability applied to the human's input, not just the agent's output."
6:30
Gate 3: the irreversible write
Screen
Post to Yardi. Strands flow outward. "Posting 196 entries · exceptions are flagged, not posted." Then "Posted to Yardi · cycle closed."
Say
"Posting is the one external write, so it has the lowest autonomy in the product. It is offered in the drawer header, where the work stopped. The agent's own instructions say it: post only records a human has approved, and if the set changed after approval, stop and ask again. Light flows outward now. Direction on the wires is meaningful: inward while reading, outward while writing."
7:05
Measuring the system
Screen
AI Performance overview: token split, three agent cards, trend chart "Records per reviewer hour".
Say
"An AI feature needs its own scorecard. Tokens are split by agent and by input, output and cached, because output is the expensive part and that is where you cut. Success rate is runs with no human correction. The trend figure I chose is records per reviewer hour, because that is the number a controller takes to their own manager. Reviewer hours are down 57% in six cycles. Which raises the risk that reviewers see fewer hard cases and lose practice, so every exception carries full evidence."
7:45
What is next, and the close
Screen
Failure catalogue slide: failed run, unclassified file, missing eighth document, conflicting rules.
Say
"Open work: a designed state for a document intake cannot identify, a missing document at the gate, and an audit trail that names who approved what. The principle behind all of it: the agent does the work, the person owns the decisions, and the product has to prove the difference."

07Decisions worth telling, and how to tell them

Use the same shape every time: the situation, the wrong version you shipped or considered, what was actually wrong with it, the fix, and what it cost. Reviewers trust a designer who names their own mistakes with precision.

The Exception agent that disappeared

Early docs list four agents: Intake, Reconciliation, Exception, Summary. The build has three. Say why: grouping exceptions and explaining a non-match is inseparable from matching, so a separate agent added a handoff without adding a decision. The token accounting moved with it (486K + 238K became one 724K line). This shows you simplify agent topologies rather than multiply them.

V1 to V2: three complaints, one redesign

The workspace read as four columns; the statement and ledger widgets were weak; the review transition was abrupt. V2 folded the agents into the canvas, shrank each document to a 68px row so four banks fit, converged all strands to a single node per side, and made review a drawer over the hub instead of a canvas swap. Then you adopted V2 and deleted V1. Show a side-by-side.

Colour that lied

Agents used to be coloured with the status palette, so a red dot sat beside Summary in a product where red means failed. You separated agent identity tokens from status tokens structurally. Then on the AI Performance page you removed agent hues entirely and used a lightness ramp for the token bar, because a hue per peer had readers hunting for a meaning that was not there.

The wire that flooded the canvas

Tinting settled strands amber meant a property with exceptions on every bank turned the whole composition amber, and the tint carried nothing the row glyphs and counts were not already carrying. Settled strands are now white over a soft dark keyline. The verdict lives on the rows. Say the principle: a state that is true everywhere discriminates nothing.

Failure copy has a register

A failed session's note is written by the system in the register of a log line, two or three words, no counts. Because a failure is raised by the pipeline before any agent has an opinion, copy that reads as a diagnosis claims reasoning that never happened. This is content design for agents: who is speaking, and what do they actually know.

08Questions you will be asked

Prepare a 30-second answer for each. The answer should end with a pointer to a specific surface in the product.

QuestionAnswer shape
How did you decide what the agent does on its own?Three tests: is the output a proposal or a write, is it reversible, how big is the blast radius. Matching passes all three, posting fails two, so posting gets the gate.
How do you stop people over-trusting it?Confidence on every decision, evidence lines, and an autonomy metric that cannot improve when a human cleans up after it.
What happens when it is wrong?Three kinds of wrong, three states: an exception (could not settle a record), an unclassified file (could not identify a document), a failed run (the pipeline broke). Each has different copy and a different route back.
How does it get better?Reviewer corrections become prose rules scoped to property or portfolio, read before every run, with hit counts so stale rules surface.
How do you design for latency?Reconciliation runs 144 seconds median. The core shows one live agent, the log fills in real time, per-bank percentages move, and the person is never staring at a spinner with no account of progress.
How do you think about cost?Tokens are split by agent and by in / out / cached, and the trend figure is tokens per record, because cost only means something against output.
How would you evaluate it before shipping?A golden set of closed cycles with known answers, measure first-pass accuracy and false approvals per agent, and gate the approval floor on that data rather than intuition.
Did you write the prompts?Yes, as design artifacts. Show "Post only records a human has approved" and "Where two instructions conflict, follow neither and route the line to a reviewer with both quoted." Those are interaction rules expressed in the agent's instructions.
What did you cut?The Exception agent, the fourth column, the Throughput tab, agent hues on the performance page, the 64px dashboard action bar, and an entire V1 workspace.
What would you do with three more months?The gaps in section 9, in this order: unclassified-file affordance, missing-document gate copy, named approvals in the audit trail, an offline eval harness.

09Gaps to own as roadmap

Say these before anyone asks. Naming the edges of your own work is a seniority signal, and each one is already listed in your V2 spec as open.

  • Unclassified document state. The model supports a document that never docks, but there is no "could not read this, assign it manually" affordance at the core.
  • Missing eighth document. Intake would finish with three banks paired and one half-open. The gate copy has no failing counterpart.
  • Named approvals. Rules are dated, not signed, because the prototype has no accounts. A real close needs who approved what, when.
  • Conflicting rules surfaced in the UI. The prompt says route with both quoted. The review row does not yet show the two quoted rules.
  • Sequential intake is a legibility choice. Real intake would fan out. Say so, and say why you kept it readable in the prototype.
  • Start next cycle. The provider supports it; the canvas does not offer it after complete.
  • Evaluation harness. The performance figures are seeded. Describe how you would generate them.
  • Reviewer deskilling. Reviewer hours fell 57%. Propose a periodic "shadow review" of auto-approved matches to keep calibration honest.

10Pre-recording checklist

Things observed in the running app today that will show up on camera if you do not handle them first.

  • Commit or stash the working tree. Several files are deleted but uncommitted (the V2 route, MainCanvas, PhaseCTA, UploadPair and others). Record from a known commit so the build is reproducible.
  • Record at 1440px wide or more. At 1024px the workspace showed only the core with no document rows or strands. The hub needs 980px of canvas after the rail and sessions panel. Confirm rows render before you start.
  • Hide the Next.js dev indicator. The "N" button sits on top of the AI Performance rail button and opened its menu twice during my pass. Set devIndicators: false in next.config.ts, or record a production build.
  • Use 1500 Park St for the full lifecycle. It is the only Not started property, so it opens in draft and lets you show drop → intake → gates → post end to end. Use 1849 Westlake for the review deep-dive since it has 8 handwritten exceptions with reasons.
  • Keep the tab visible while recording. Chrome throttles timers and pauses animation frames in hidden tabs. Your own notes say the intake cadence looks three times slower when the pane is hidden.
  • Font check. Your typography doc records that TASA Orbiter was not loading and everything fell back to Geist. Decide which face is on camera and make sure it is the one that renders.
  • Sessions panel collapsed for the hub, expanded for navigation beats. Collapsed gives the hub room; expanded shows the property-to-session hierarchy.
  • Capture hover isolation deliberately. Hover one row for a full second so the other seven strands visibly drop to 20%.
  • Record the Undo toast. Approve a record, let the toast appear, then click Undo. That single interaction proves reversibility.
  • Screen at 2× device pixel ratio, export at 1920×1080 or 2560×1440, 60 fps. The strand animation and the dot-field avatars smear at 30 fps.
  • Cursor. Slow, deliberate, no wiggling. Pause on each number you name.
  • Voice. Record narration separately and cut the screen to it. Screen recordings narrated live run long and hesitate.

11Frameworks and reading to cite

Cite two or three of these by name in the case study. It signals you are working inside a discipline, not inventing vocabulary. Read the source before citing it and describe it in your own words.

Levels of automation
Parasuraman, Sheridan and Wickens' model of automation levels across information acquisition, analysis, decision, and action. Your autonomy ladder is this idea applied per pipeline step.
Human-AI interaction guidelines
Microsoft's HAX guidelines (Amershi et al.) and Google's People + AI Guidebook. Both cover making capabilities clear, showing why the system did what it did, supporting efficient correction, and learning from user behaviour. Map your surfaces to specific guidelines.
Workflows vs agents
Anthropic's "Building effective agents" distinguishes predefined workflows from open-ended agents and describes patterns like prompt chaining and orchestrator-workers. Reconciler is a workflow with agentic steps, and saying so precisely is a credibility point.
Ironies of automation
Lisanne Bainbridge's 1983 paper on how automation leaves humans with the hardest cases and the least practice. Cite it when you discuss the 57% drop in reviewer hours.
Gulfs of execution and evaluation
Don Norman. Observability closes the gulf of evaluation: the person can tell what state the system is in and whether their action worked.
Calibrated trust
Lee and See's work on trust in automation. Trust should track actual reliability. Your frozen autonomy metric is a calibration device.
AI pattern libraries
Shape of AI and similar pattern collections give you shared names for things like confidence indicators, citations, and undo. Use their names where they match yours.
